# 测试执行器功能测试计划

针对测试执行器核心功能的全面测试计划，覆盖正向流程、异常处理、边界条件、数据验证、状态转换及安全权限等维度，基于React/Vite技术栈设计，使用Playwright语义化定位器确保自动化测试可执行性。

## 正向流程 - 正常执行测试套件

**Steps:**

1. 导航到测试执行器页面 → `getByRole('link', { name: '测试执行器' })`
2. 选择测试套件 → `getByLabel('选择测试套件')`
3. 选中核心业务回归套件 → `getByRole('option', { name: '核心业务回归' })`
4. 选择执行环境 → `getByLabel('执行环境')`
5. 选中Staging环境 → `getByRole('option', { name: 'Staging' })`
6. 点击开始执行按钮 → `getByRole('button', { name: '开始执行' })`
7. 等待执行状态更新 → `getByRole('status', { name: '执行完成' })`

**Expected Results:**

- 页面成功加载执行器表单，下拉选项渲染完整
- 套件与环境选择后UI正确回显选中状态
- 点击执行后任务创建成功，状态变更为运行中
- 进度条实时更新，最终状态显示为执行完成
- 执行报告展示100%通过率，无异常日志

## 反向/异常流程 - 必填参数缺失拦截

**Steps:**

1. 导航到测试执行器页面 → `getByRole('link', { name: '测试执行器' })`
2. 选择测试套件 → `getByLabel('选择测试套件')`
3. 选中核心业务回归套件 → `getByRole('option', { name: '核心业务回归' })`
4. 保持执行环境为空 → `getByLabel('执行环境')`
5. 点击开始执行按钮 → `getByRole('button', { name: '开始执行' })`
6. 检查表单验证提示 → `getByRole('alert')`

**Expected Results:**

- 表单验证机制拦截提交请求
- 执行环境输入框下方显示红色错误提示：请选择执行环境
- 开始执行按钮保持禁用状态或点击后无网络请求发出
- 未创建任何执行任务，系统状态无变化

## 边界值测试 - 最大并发数与空测试集

**Steps:**

1. 导航到测试执行器页面 → `getByRole('link', { name: '测试执行器' })`
2. 输入并发数最大值 → `getByLabel('并发数')` = "100"
3. 选择测试套件 → `getByLabel('选择测试套件')`
4. 选中空测试集 → `getByRole('option', { name: '空测试集' })`
5. 点击开始执行按钮 → `getByRole('button', { name: '开始执行' })`
6. 检查执行结果状态 → `getByRole('status', { name: '执行完成' })`

**Expected Results:**

- 并发数输入框限制最大输入值为100，超出部分自动截断或提示警告
- 空测试集执行瞬间完成，不触发实际用例调度
- 状态显示为执行完成（0/0），耗时接近0ms
- 系统无内存泄漏、无崩溃，日志记录空集执行事件

## 数据验证 - 执行结果完整性与格式校验

**Steps:**

1. 点击开始执行按钮 → `getByRole('button', { name: '开始执行' })`
2. 等待执行完成 → `getByRole('status', { name: '执行完成' })`
3. 定位执行结果表格 → `getByRole('table', { name: '执行结果' })`
4. 检查特定用例行数据 → `getByRole('row', { name: 'TC-001' })`
5. 验证状态单元格 → `getByRole('cell', { name: '通过' })`
6. 验证耗时单元格 → `getByRole('cell', { name: '125ms' })`

**Expected Results:**

- 结果表格包含用例ID、状态、耗时、错误信息等必填列
- 数据格式严格符合规范（耗时为数字+单位，状态为枚举值）
- 所有字段无null、undefined或空字符串异常值
- 前端展示数据与后端执行日志完全一致，无数据丢失

## 状态转换 - 执行状态流转与取消操作

**Steps:**

1. 点击开始执行按钮 → `getByRole('button', { name: '开始执行' })`
2. 等待进度条出现 → `getByRole('progressbar')`
3. 点击取消执行按钮 → `getByRole('button', { name: '取消执行' })`
4. 验证最终状态 → `getByRole('status', { name: '已取消' })`

**Expected Results:**

- 状态按待执行->运行中->已取消顺序正确流转
- 点击取消后进度条立即停止更新并隐藏
- 取消按钮变为禁用或自动隐藏，防止重复点击
- 后端任务状态同步更新为CANCELLED，无残留后台进程

## 安全/权限 - 未授权用户越权执行拦截

**Steps:**

1. 以只读角色登录系统 → `getByRole('link', { name: '登录' })`
2. 导航到测试执行器页面 → `getByRole('link', { name: '测试执行器' })`
3. 尝试点击开始执行按钮 → `getByRole('button', { name: '开始执行' })`
4. 检查权限拦截提示 → `getByRole('alert', { name: '权限不足' })`

**Expected Results:**

- 开始执行按钮对只读角色隐藏或置灰不可点击
- 若通过开发者工具强制触发API，后端返回403 Forbidden
- 页面显示明确提示：您无权执行测试任务
- 未触发任何测试运行，审计日志记录越权尝试

## 异常处理 - 执行超时与自动重试机制

**Steps:**

1. 设置超时时间 → `getByLabel('超时时间(秒)')` = "5"
2. 点击开始执行按钮 → `getByRole('button', { name: '开始执行' })`
3. 等待超时触发 → `getByRole('log')`
4. 点击重试失败用例按钮 → `getByRole('button', { name: '重试失败用例' })`

**Expected Results:**

- 超过5秒后对应用例标记为超时失败
- 错误日志准确记录TimeoutError及堆栈信息
- 重试按钮在失败用例出现后变为可用状态
- 点击重试后仅重新调度失败用例，结果状态更新为最新执行数据

## 并发控制 - 多任务排队与资源隔离

**Steps:**

1. 首次点击开始执行 → `getByRole('button', { name: '开始执行' })`
2. 立即再次点击开始执行不同套件 → `getByRole('button', { name: '开始执行' })`
3. 监控执行队列面板 → `getByRole('list', { name: '执行队列' })`
4. 验证排队任务状态 → `getByRole('status', { name: '排队中' })`

**Expected Results:**

- 系统根据并发限制将第二个任务置为排队中状态
- 队列按FIFO顺序调度，不出现任务丢失或乱序
- 两个任务执行结果互不干扰，数据隔离正确
- 系统资源占用在安全阈值内，状态面板实时反映队列变化
